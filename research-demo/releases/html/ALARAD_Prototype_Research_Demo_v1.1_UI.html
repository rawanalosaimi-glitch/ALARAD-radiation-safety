Model Input

What this engine is — and is not

It is a rule-based anomaly and risk-assessment prototype with a simple linear-regression forecast. It is not a trained or validated AI/ML model, and it has not been tested on real dosimeter data.

Computed live from your inputs: estimated worker-position rate, relative deviation from baseline, projected task dose (rate × duration, assuming a constant rate), the risk class, and the regression slope/forecast.

Simulated: the "trailing history" bars are seeded pseudo-data derived from your inputs — not real measurements; the Live Demo readings, staff doses and wearable values are also simulated.

Configurable placeholders: the room/procedure baseline table, procedure multipliers, shielding factors and the warning thresholds below. They are not regulatory limits.

Outputs are risk levels and alert recommendations for Radiation Safety Officer review — never a medical decision. A production system would need calibrated dosimeters, a validated model and regulatory review.

Official occupational dose limits (reference — not editable here)
ICRP Publication 103 recommends an effective-dose limit of 20 mSv per year, averaged over defined 5-year periods, with no single year above 50 mSv. In Saudi Arabia the applicable limit and averaging period are set by NRRC requirements (e.g. NRRC-R-01-SR02) — consult the current official text. Compliance decisions belong to the Radiation Safety Officer. This prototype's year-to-date status badges use 20 mSv only as a visual reference level and do not model the 5-year average.

Data Security DESIGN TARGET

ℹ
This page describes the intended production architecture. None of these controls (TLS, AES-256, certificate pinning, role-based access, audit logging) is implemented in this single-file prototype, which has no backend, no network transmission and no authentication.
📡

Secure Connection

Wearable → mobile app → cloud runs over an authenticated TLS session; the device only transmits to the paired ALARAD gateway, never to an open network.

  • TLS 1.2+ channel
  • Certificate-pinned mobile app
  • No data leaves the hospital OT/IT boundary unencrypted
🔐

Encryption

Data is encrypted in transit and at rest, so dose, biometric, and location data cannot be read if intercepted or if storage is accessed directly.

  • AES-256 at rest
  • End-to-end encrypted transmission
  • Encrypted backups, key rotation
🪪

Authentication

Every device and dashboard session is tied to a verified Employee ID; only authorized RSO/admin accounts can view hospital-wide data.

  • Device pairing tied to Employee ID
  • Role-based dashboard access (RSO / admin / staff)
  • Session tokens, audit-logged access

Method and notes

Calculation method

Time step = 1 minute, 60 steps per scenario. Each step calls evaluateExposure() with a 30-minute projection horizon (the engine's "projected task dose" factor). Incremental dose per step: Dose (mSv) = Dose Rate (µSv/h) × Duration (h) / 1000, with each reading held constant over its minute; accumulated dose is the running sum. Measured personal-dosimeter readings are used as is. Area-monitor readings are converted by the engine to a modeled worker-position estimate reading × (reference distance ÷ worker distance)² × shielding; distance and shielding are applied only to area readings. Measured and modeled values are stored and plotted separately. Inverse-square scaling is only a limited point-source approximation; scatter in real rooms does not follow it. Readings that are missing, negative, not finite or above 1,000,000 µSv/h are rejected before the engine and add no dose.

Prediction, detection and incident response are different things

Prediction = linear extrapolation of the last 4 readings (the existing linearForecast) projecting a deviation at or above the elevated threshold within 3 minutes while the engine is still LOW. Detection = the engine's current-reading check. Incident response = acknowledge, action and resolve by the RSO. It is not simulated in the Lab; use the Live Demo for the workflow. Simulated thresholds are configurable warning levels, not regulatory dose limits. Annual cumulative dose is not used as an instantaneous danger threshold, and no annual line is drawn on any chart.

The evaluation rules (event matching, metrics, latency), the sensitivity analysis and the complete list of limitations are in the Validation & Results section above.

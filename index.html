ℹ

Model Input

Input: dose rate · time · room · procedure · distance · shielding

Model Honesty Note

This is a lightweight, fully computed statistical model — not a lookup table. It uses: (1) a procedure-baseline expected dose-rate table, (2) an inverse-square distance correction, (3) a shielding attenuation factor, (4) a rolling 6-point trailing series with linear-regression forecasting, and (5) a z-score-style deviation check to flag anomalies. Every value below is recalculated live from your inputs — see src/domain/riskEngine.js.

Production version: replace the baseline table with a trained time-series model (e.g. Prophet / LSTM) fitted on real dosimeter history, and replace the linear trend with the model's own forecast output — only riskEngine.js would need to change.

Proposed Security Architecture

البنية الأمنية المقترحة
PROPOSED — NOT YET IMPLEMENTED IN PRODUCTION
📡

Secure Connection

Wearable → mobile app → cloud runs over an authenticated TLS session; the device only transmits to the paired ALARAD gateway, never to an open network.

  • TLS 1.2+ channel
  • Certificate-pinned mobile app
  • No data leaves the hospital OT/IT boundary unencrypted
🔐

Encryption

Data is encrypted in transit and at rest, so dose, biometric, and location data cannot be read if intercepted or if storage is accessed directly.

  • AES-256 at rest
  • End-to-end encrypted transmission
  • Encrypted backups, key rotation
🪪

Authentication

Every device and dashboard session is tied to a verified Employee ID; only authorized RSO/admin accounts can view hospital-wide data.

  • Device pairing tied to Employee ID
  • Role-based dashboard access (RSO / admin / staff)
  • Session tokens, audit-logged access

RAG Architecture (as deployed in this prototype)

Official Documents → PDF/Text extraction → Chunking → (Prototype: keyword-weighted match in domain/knowledgeEngine.js. Production: Embeddings) → Vector Database → User Question → Semantic Retrieval → Top relevant chunks → LLM → Answer + Source + Page.

The "Ask ALARAD AI" tab implements this full chain end-to-end using the 7 reference documents in the Knowledge Base panel; each answer cites the specific source document and a page reference, and low-confidence matches return "I could not find a matching topic" rather than a fabricated answer.

Human-in-the-Loop

Model outputs (predicted dose, risk level, anomaly flags) are checked against dose limits; high-risk alerts are reviewed by a Radiation Safety Officer before escalation — enforced in this prototype via the "Report to Radiation Safety Officer" action on the Emergency / GPS page.
